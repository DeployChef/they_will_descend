Журнал работ по аудио-системе. Обновляется по ходу разработки.

## Что сделано (сессия: переход на 120 аудио-зон + FMOD-интеграция)

### 1. Аудио-зоны вместо ячеек
- Удалены старые `AudioCell.cs`, `AudioCellSettings.cs`, `AudioGridManager.cs` (было 14 592 инстанса — перебор).
- Теперь **120 зон** = 12 угловых секторов × 10 дистанционных колец.
- Одна зона = конус 30° × кольцо ~12м (0–120м). Один FMOD Instance на зону.
- **Один инстанс на зону, не на ячейку** — 120 инстансов вместо 14 592.

### 2. Файлы системы
- `Presentation/Audio/AudioZoneSettings.cs` — ScriptableObject: секторы, кольца, дистанция, путь ивента, имя Distance-параметра, дебаг-логи.
- `Presentation/Audio/AudioZone.cs` — зона: FMOD-инстанс, 3D-атрибуты, RTPC, регистрация построек, Gizmos.
- `Presentation/City/AudioZoneManager.cs` — менеджер: строит 120 зон, тик видимости каждые 2 кадра, Distance-параметр + 3D каждый тик, загрузка банков, fallback-центр (0,0,0) если DOTS-сетка не готова 3 сек.
- `Presentation/City/AudioVisibilityChecker.cs` — проверка видимости: горизонтальный FOV (пересчёт из вертикального через aspect), forward выровнен по горизонтали.
- `Presentation/City/BuildingAudioSource.cs` — компонент на постройку: тип (House/Workshop/Market/...), activity weight, авто-регистрация в зоне.
- `Presentation/Audio/FmodBankLoader.cs` — загрузчик банков: Master + банки из поля Fmod Banks, кеш, BankLoadException → Warning.
- `Presentation/City/BuildingViewBoard.cs` — при спавне постройки регистрирует её в ближайшей зоне (`FindZoneNear`).

### 3. main_soundtrack отключён
- В `GameAudio` флаг `enableMusic` (по умолчанию **off**): `StartSessionMusic()` при off не запускает трек, `Awake()` принудительно глушит.
- `PlayingState` больше не вызывает `StartSessionMusic()` — только `StopSessionMusic()` на входе.
- Вернуть музыку: галка Enable Music в инспекторе GameAudio.

### 4. Ивент ambience_town привязан
- Путь ивента: `event:/audio/city/ambience_town` (в AudioZoneSettings).
- RTPC/параметры: `Has_Houses`, `Has_Workshops`, `Has_Market`, `Cell_Activity` (0–1), **Distance** (0–100, нормализация: метры / 120 × 100).

### 5. Логика звучания зоны (текущая)
- Зона звучит **только если**: (а) в поле зрения камеры, (б) в зоне есть постройки.
- Пустая зона — инстанс не создаётся. Снос всех построек — инстанс глушится сразу.
- 3D-позиция и Distance обновляются каждый тик видимости.
- Затухание по отдалению: 3D-позиция инстанса + Distance-параметр (audio LOD в FMOD Studio).

### 6. Дебаг
- Gizmos рисуются всегда (флаг Show Gizmos у AudioZoneManager).
- Цвета: ярко-зелёный — видна и звучит; жёлто-зелёный — видна, но FMOD-ивента нет; красный — мёртвое состояние (за камерой/пустая). Маркер-сфера: голубая — видна, красная — мертва.
- Логи ACTIVATED / DEACTIVATED (с пометкой no buildings), логи только один раз, не спам.

### 7. Исправленные баги
- `float3 != float3` возвращает `bool3` → заменили на `!math.all(a == b)`.
- Центры зон стояли на границах секторов → угол середины сектора `(Sector + 0.5f)`.
- Цвет зон не менялся за камерой → цвет завязан на `IsVisible` (геометрия), а не на `IsActive` (зависел от несуществующего FMOD-ивента).
- Зоны работали только у центра → горизонтальный FOV + выравнивание forward.
- Спам ошибок «Event not found» 14 592 раза → лог один раз.
- **Звук не появлялся при постройке здания.** Причина: `BuildingAudioSource.OnEnable()` срабатывает в момент `AddComponent` — до присвоения `LinkedZone`, поэтому регистрация в зоне проваливалась, зона оставалась «пустой» и не активировалась. Исправление:
  - `BuildingViewBoard.RegisterAudioSource` теперь явно вызывает `zone.AddAudioSource(source)` после присвоения `LinkedZone`;
  - если зона уже в поле зрения камеры — мгновенная активация (`zone.SetActive(true)`) прямо в момент постройки, без ожидания тика;
  - `AudioZoneManager.BuildZones` при пересоздании зон (сдвиг центра сетки) перелинковывает все существующие `BuildingAudioSource` в новые зоны (`RelinkExistingSources`) — раньше ссылки оставались на мёртвые объекты зон.

### 9. Звука нет — найдены и устранены 3 причины (сессия дебага)
- **Банки не были в StreamingAssets.** Банки собирались FMOD Studio в `Audio_FMOD/they will desend/Build/Desktop/`, а в `Assets/StreamingAssets/Desktop/` лежали только старые Master. Скопированы: `Ambience_Town.bank`, `Ambience_Wind_Generator.bank`, `Main_theme.bank`, `Master.bank`, `Master.strings.bank`. **При изменениях в FMOD Studio — пересобирать (Ctrl+B) и копировать банки заново.**
- **Ссылка BuildingViewBoard → AudioZoneManager пустая.** Менеджер живёт в Bootstrap-сцене (грузится additive), сериализованная cross-scene ссылка невозможна (`fileID: 0` в Game.unity). Фикс: `RegisterAudioSource` теперь сам делает `FindFirstObjectByType<AudioZoneManager>()` при пустой ссылке.
- **Страховка камеры в AudioVisibilityChecker.** Если камера появляется позже Bootstrap, `Camera.main` в Awake был null и видимость никогда не считалась. Теперь камера ищется лениво в `UpdateVisibility`.
- Конфигурация подтверждена правильной: ассет `New Audio Zone Settings.asset` → `eventPath: event:/Ambience_Town` (ивенты лежат в корне FMOD-проекта, НЕ в `audio/city/`), банк в сцене `Ambience_Town`.

### 10. Hot reload банков (принцип StudioEventEmitter)
- **EventReference в AudioZoneSettings** — ивент перетаскивается из FMOD Studio в инспектор (как у StudioEventEmitter), строковый путь остался как fallback.
- **Автоопределение банков:** если EventReference задан, банки грузятся автоматически из описания ивента (`StudioSystem.getBankList` → перебор банков → `bank.getEventList` → сравнение путей). Ручной список Fmod Banks — fallback.
- **Hot reload кнопкой:** у AudioZoneManager контекстное меню **Reload FMOD Banks** (правой кнопкой по заголовку компонента в инспекторе во время Play): глушит зоны → выгружает ивентовые банки → грузит заново → пересоздаёт зоны → перелинковывает постройки. Master/Master.strings не выгружаются (без strings не резолвятся пути ивентов).
- **FmodBankLoader:** добавлены `UnloadBanks`, `UnloadEventBanks`, `GetBanksForEvent` и `LoadBanksForEvent(EventReference)`.
- Найденные ошибки API: у `Bank` нет `getName` — только `getPath` (возвращает `bank:/ИмяБанка`); у `EventDescription` в FMOD 2.03 **НЕТ** `getBankList` (CS1061) — банки ивента ищутся перебором банков системы. Обе внесены в AGENTS.md.

**Как пользоваться hot reload:**
1. Перетащи ивент `Ambience_Town` в поле **Event Reference** ассета New Audio Zone Settings (окно FMOD → Event Browser → перетащить мышкой).
2. Поменял что-то в FMOD Studio → Ctrl+B → скопируй `.bank` в StreamingAssets.
3. Во время Play: правой кнопкой по заголовку AudioZoneManager в инспекторе → **Reload FMOD Banks**. Звук подхватится без перезапуска сцены.

### 12. Дистанционная смерть зон (audio LOD-куллинг)
- **Суть (запрос Валентина):** умирание голосов — это про **локальные ивенты (звуки города, зоны)**, не про глобальные. Дальняя зона, попавшая в угол обзора, не должна жить на 120м — при максимальном Distance инстанс умирает полностью.
- `AudioZone.UpdateDistanceDeath(camPos, deathDistance, hysteresis)`: dist ≥ Death Distance → `ReleaseInstance()` (звук не существует, систему не грузит); возрождение при dist < Death Distance − Hysteresis (зона видима и не пуста). Логи KILLED/REVIVED.
- Настройки в AudioZoneSettings: **Zone Death Distance** (по умолч. 100м — меньше MaxDistance 120, чтобы дальнее кольцо не звучало), **Zone Death Hysteresis** (5м).
- Вызывается каждый тик видимости из AudioZoneManager перед UpdateDistanceRtpc.
- Итого жизнь инстанса зоны: (а) в поле зрения камеры, (б) есть постройки, (в) ближе Death Distance. Любое условие отпало — инстанс release.

## Что сделано (сессия: глобальные ивенты атмосферы)

### 11. GlobalAmbienceManager (Presentation/Audio/GlobalAmbienceManager.cs)
- **Один компонент — список глобальных ивентов** (ветер и будущие). Кладётся на Bootstrap рядом с GameAudio.
- Глобальный ивент = **один инстанс на весь мир**, не режется на зоны, не зависит от поля зрения камеры.
- **Distance-принцип:** дистанция камеры до опорной точки ивента (центр города из DOTS или ручная Anchor Point) двигает Distance-RTPC (0–100, нормализация dist/deathDistance × 100).
- **Смерть при максимальном отдалении:** dist ≥ Death Distance → инстанс `stop(ALLOWFADEOUT)` + `release()` — **звук не существует, систему не нагружает**. Возрождение при dist < Death Distance − Hysteresis (гистерезис против дёрганья на границе).
- 3D-позиция инстанса следует за камерой (звук «вокруг»), затухание управляется только Distance-RTPC.
- Банки каждого ивента находятся автоматически (`FmodBankLoader.LoadBanksForEvent`).
- **Пауза:** публичный `SetPaused(bool)` — подключить к паузе игры (механику паузы Валентин придумает позже).
- OnDisable убивает все инстансы — при выключении компонента ничего не звучит.
- Поля ивента в инспекторе: Event Reference (drag-and-drop), Distance RTPC (по умолч. `Distance`), Death Distance (по умолч. 120), Hysteresis (по умолч. 5), Anchor Point / Use City Center.

**Как добавить новый глобальный ивент:**
1. Повесить GlobalAmbienceManager на Bootstrap (если ещё не повешен).
2. В списке Events добавить элемент → перетащить ивент из FMOD → Event Browser в Event Reference.
3. У ивента в FMOD Studio должен быть Distance-параметр (0–100) с автоматизацией громкости/слоёв.
4. Банк подхватится сам (если собран и скопирован в StreamingAssets).

### 13. Ветер не слышен — 2 причины исправлены
- **Death Distance = 120 убивал ветер ровно при максимальном отдалении.** Ветер привязан к центру города, камера дальше 120м → инстанс release → тишина. Но ветер по задумке должен звучать при отдалении (город затихает — ветер остаётся). Исправление: **Death Distance = 0 → смерть отключена** (ивент звучит всегда). Для ветра поставить 0 в инспекторе.
- **distanceRtpc пустая строка в сцене** — Unity сериализовал пустоту, Distance-RTPC не выставлялся, ивент молчал на дефолтном значении параметра. Исправление: код теперь treats пустую строку как `"Distance"`; в инспекторе вписать `Distance`.
- Новое поле **RTPC Range** (по умолч. 120м) — диапазон нормализации Distance-RTPC, независимый от Death Distance.
- Итог для ветра в инспекторе: Distance RTPC = `Distance`, **Death Distance = 0**, RTPC Range = 120, Use City Center = вкл.
- В FMOD Studio проверить автоматизацию ветра: Distance 0 (у центра города) → тише, Distance 100 (120м+) → громче.

### 14. Параметр Distance в FMOD — не того типа (корень тишины ветра)
- **Найдено по метаданным** (`Metadata/ParameterPreset/*.xml`): параметр `Distance` в ивентах — `parameterType: 3` (**AUTOMATIC_EVENT_ORIENTATION** — автоматический параметр FMOD, переименованный в Distance) и `isExposedRecursively: false` (не экспонирован в API).
- Следствия: в Event Browser параметр не виден (Валентин это заметил); `setParameterByName("Distance")` из кода молча не работает; значение всегда = initialValue 0 → громкость, автоматизированная от параметра, стоит в нуле → **голоса не звучат, профайлер пустой**.
- **Касается обоих ивентов** — Ambience_Town использует тот же параметр (тот же GUID). Distance-RTPC города тоже не работал.
- **Исправление в FMOD Studio (вручную):** удалить автоматический параметр → создать новый **Game Parameter** `Distance` (0–100, exposed) → перепривязать автоматизации → Ctrl+B → скопировать банки в StreamingAssets. Код менять не нужно.
- Правило внесено в AGENTS.md: RTPC из кода управляет только Game Parameter (parameterType 0); автоматические (1–9) и unexposed — нет.

### 15. Звук города звучит до постройки здания — исправлено
- **Причина:** `RelinkExistingSources` искал `BuildingAudioSource` по всей сцене, включая отключённые объекты и префабы, которые ещё не были уничтожены Unity (`pending destruction`). `IsEmpty()` возвращал `false` на пустой зоне → `CreateInstance()` запускался раньше появления реальных построек.
- **Фикс 1:** `RelinkExistingSources` теперь строго фильтрует только активные объекты (`activeInHierarchy`), игнорируя уничтожаемые/отключённые.
- **Фикс 2:** `AudioZone.SetActive` теперь требует `ActivityLevel > 0.01f` для активации. Если построек нет, зона не звучит даже при видимости.
- **По стримингу:** стриминг в FMOD не ломает параметры. Проблема была в типе параметра (automatic + unexposed), а не в стриминге. После создания Game Parameter в FMOD Studio всё заработает корректно.

## Как смотреть RTPC-параметры в реальном времени (Live Update)

1. В Unity: **FMOD → Edit Settings** → в секции нужной платформы (или Default) включить **Live Update** (галочка tri-state), под ней появится **Live Update Port** — порт **9264** (Reset возвращает порт). Галочки per-platform — включать в секции той платформы, на которой идёт игра.
2. Запустить Play в Unity.
3. В FMOD Studio: **Window → Connect** (F5) → выбрать игру в списке → **Connect**.
4. Открыть ивент `Ambience_Town` — в микшере в реальном времени видно уровни дорожек и текущие значения RTPC (Has_Houses, Has_Workshops, Has_Market, Cell_Activity, Distance). Двигаешь камеру / строишь здания — параметры двигаются вживую.
5. **Window → Profiler** — голоса, CPU, все играющие инстансы и их параметры (видно все 120 зон).
6. Оверлей поверх игры: там же в FMOD Settings включить **Debug Overlay** (появятся Debug Location и Font size) — в углу Game View видно играющие ивенты и их параметры прямо в игре, без FMOD Studio.
