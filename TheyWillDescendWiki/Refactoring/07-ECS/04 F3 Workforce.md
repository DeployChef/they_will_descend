# 04. Ф3 — Честный desired state

**Статус: сделано** (2026-10-27). `DesiredWorkers` пишет только UI / restore / spawn. Пауза не отпускает штат. Раздача по `Building.Id`. Сводка `WorkforceSummary` на сессии.

← [[03 F2 Entity Identity]] | [[Index]] | далее [[05 F4 Inputs]]

Делать после Ф2: диспетчер уже ходит по `Entity`.

Цель: `DesiredWorkers` неприкосновенно для систем; пауза не отпускает людей; недобор виден; раздача детерминирована по `Building.Id`.

## 1. Баг, который чиним

`WorkforceDispatchSystem` сейчас (смысл, не копировать):

```csharp
var desired = workplace.IsPaused ? 0 : clamp(DesiredWorkers, 0, slots);
// ...
if (needed > 0 && нет свободных)
    workplace.DesiredWorkers = current + assigned;   // УБИТЬ ЭТУ СТРОКУ
```

Следствия:

1. Смерть/нехватка людей навсегда уменьшает желание.
2. Пауза отпускает штат — против решения Ф0.1. Комментарий `Workplace.Paused` («assigned workers stay») уже врёт относительно кода.
3. UI (`CountWorkforce`) считает свободных как «все минус сумма желаний» — другая формула, чем у системы (система смотрит фактические назначения). Кнопка «+» врёт относительно диспетчера.

## 2. Целевой тик диспетчера

Группа: как сейчас, `UpdateBefore(AdvanceAgentCommuteSystem)`.

Гейт: **не работать при `SimControl.Mode == Off`**. На `TimePaused` / `PlayerPaused` выравнивать штат можно (игроку удобно тыкать +/- на паузе). `IsRunning` для диспетчера не обязателен.

```text
1. Собрать агентов-рабочих:
     free = Workplace == Null (или HasComponent<Workplace> == false → вылечить в Null)
     assigned[entity] = список агентов
2. Собрать дома WithAll<Workplace> WithNone<Construction>
     отсортировать по Building.Id возрастанию
3. Для каждого дома:
     target = min(DesiredWorkers, slots)     // Paused ИГНОРИРУЕТСЯ
     если факт > target: отпустить лишних (с конца списка назначенных этого дома)
     если факт < target: взять из free
     НЕ писать DesiredWorkers
     Workplace.AssignedCount = факт
4. WorkforceSummary на сессию
```

`Paused` читает только `BuildingProductionSystem` (уже skip `IsPaused`) и UI (иконка). Рецепт стоит, люди на работе, `WorkingCount` может быть > 0 — это ок: «на месте, но станок выключен». Если продукция смотрит `WorkingCount` и `IsPaused` — пауза побеждает. Не обнулять WorkingCount из-за паузы.

### WorkforceSummary

Новый компонент на сессии, пишет **только** диспетчер:

```csharp
public struct WorkforceSummary : IComponentData
{
    public int TotalWorkers;
    public int IdleWorkers;      // Workplace == Null
    public int DesiredTotal;     // сумма DesiredWorkers по готовым домам
    public int UnmetDesired;     // сумма max(0, target - assigned)
}
```

UI больше не сканирует всех агентов, чтобы посереть «+». Ф5 дочитает; в Ф3 уже можно перевести `BuildingInspectPanel.CountWorkforce` на этот синглтон, если файл открыт — лучше сразу, чтобы не держать ложную формулу.

### SyncWorkplaceLoadSystem

Оставляет `WorkingCount` (дошли, не на стройке). `AssignedCount` — владелец диспетчер. Не считать Assigned во второй раз.

Либо влить WorkingCount в диспетчер (ему нужны Arrived). Если вливаете — удалить Sync как отдельную систему, поправить `UpdateAfter` у `BuildingProductionSystem`.

## 3. Снос и желание

`BuildingDismantle.Begin` сейчас: `DesiredWorkers = 0`, `Paused = 1`, полный проход агентов.

После Ф3:

- На время сноса дом в `Construction` → диспетчер его не видит (`WithNone<Construction>`) → не назначает новых.
- Уже назначенные: либо сбросить `Workplace = Null` точечно по этому entity (Ф2), либо диспетчер на домах в Construction отпускает всех. Выбрать одно, не оба.
- **Не писать `DesiredWorkers = 0`.** Дом всё равно умрёт в `Complete`. Если снос отменят когда-нибудь в будущем — желание игрока сохранилось бы; сейчас отмены нет, но принцип тот же.

## 4. UI кнопки штата (можно в Ф3, обязательно не позже Ф5)

`BuildingInspectPanel`:

- «+» серый, если `DesiredWorkers >= slots` **или** `IdleWorkers == 0` (из сводки). Второе — чтобы не обещать невозможное. Желание при клике всё равно можно было бы поднять (система не против желания выше факта), но UX: серить, когда свободных нет — ок, **если** не записываете в систему clamp. Альтернатива канона 07: «+» серый только по slots; недобор показывает строка «3/5, не хватает людей». **Канон этой папки:** серить «+» только по `DesiredWorkers >= slots`. Недобор — текст. Иначе игрок не сможет «заказать» людей заранее, пока они на другом доме. Это согласуется с «желание неприкосновенно».

Перечитать 07 §2.2: «UI может серить +, когда DesiredWorkers >= slots. Проверку есть ли свободные UI делает по сводке». Там оба. Конфликт с «заказать заранее».

**Решение для агента (зафиксировать):**

- `+` / max+ активны, пока `DesiredWorkers < slots` (и дом не в стройке).
- Свободные люди **не** блокируют желание.
- Строка штата: `{assigned} / {desired}` или `{desired} / {slots}` плюс если `assigned < desired` — видно недобор (число или цвет).
- Сводка `IdleWorkers` нужна для плашки «свободных: N», не для блока кнопки.

Сейчас кнопки блокируются ещё и `freeWorkers > 0` — это убрать.

Запись по-прежнему прямая в `Workplace.DesiredWorkers` (поле желания, не request).

## 6. Узкие места

**Порядок отпуска.** «Лишних с конца списка назначенных» — список агентов внутри дома должен быть стабилен (например по `AgentId`). Иначе кто уйдёт при снижении штата 5→4 прыгает между запусками.

**Стройка и штат.** Дом с `Construction` не в запросе диспетчера. `Workplace` на недостроенном доме может существовать (SpawnHouse вешает Workplace сразу). Пока висит Construction, штат не раздаётся — как сейчас `WithNone<Construction>`. Не менять.

**Ночь.** Назначение штата 24/7; ходить на работу — только смена (`AdvanceAgentCommuteSystem`). Не смешивать. Пауза не должна отправлять людей на плазу.

**Burst.** Сортировка NativeList по Id в Burst ок. Не использовать managed List.

**Два прохода агентов.** Сначала собрать, потом писать assignment. Не мутировать workplace во время итерации Query домов, если query структурно не позволяет — как сейчас, отдельный список entity домов.

**WorkforceDispatch без Require Workplace.** Если домов нет, сводка всё равно нужна (все idle). Сейчас `RequireForUpdate<Workplace>` — при нуле домов система не бежит, сводка устареет. Снять Require или писать сводку в другой системе при пустом запросе. **Узкое место:** после сноса последнего дома HUD покажет старых idle. Починить в Ф3.

## 7. Сценарии Play (обязательные)

1. Желаю 5, свободных 3: назначено 3, желание остаётся 5. Заспавнил 2 — через тик назначено 5 без кликов.
2. Пауза дома: люди остаются assigned, рецепт стоит, счётчик штата не падает. Снять паузу — производство без переназначения.
3. Штат 5→2: уходят двое, желание 2, трое работают.
4. Два дома хотят больше, чем есть люди: при одинаковом сейве одни и те же дома получают людей (меньший Building.Id первый).
5. Снос с полным штатом: люди на плазе, желание на уничтоженном доме не важно.

Grep: `DesiredWorkers\s*=` в `Simulation/` — только restore (если restore в Simulation) и ни одной системы. `BuildingDismantle` больше не присваивает.
