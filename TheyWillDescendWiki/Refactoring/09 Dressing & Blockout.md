# 09. Декорации и блокаут: один ран, разные сцены

← [[08 Shell, Scenes & Audio|08 Shell]] | [[Index|План рефакторинга]] | [[../Home|Главная вики]]

Цель: держать рядом с `Game.unity` лёгкую сцену `GameBlockout.unity`. Функционал тот же 1:1: сетка, установка, дороги, люди, HUD, пауза, звук мира. Вместо моделей, лавы, частиц и десятков источников света — простые блоки. Сцена нужна, чтобы быстро грузиться и не держать в памяти тяжёлый арт.

Идёт **до** логических фаз [[07 Foundation Fixes|07]] (Ф1–Ф5). Игровую логику ECS этот документ не трогает.

---

## 0. Главное правило: Game не знает про блокаут

```text
GameBlockout.unity ──► общий ран (префаб) и данные ◄── Game.unity
        │                                                ✗ ни одной ссылки на блокаут
        └──► Assets/_Project/Blockout/*  (сцена, набор облика, кубики, материалы)
```

1. **Game ни разу не ссылается на блокаут.** Ни на сцену, ни на набор облика, ни на материалы. В коде нет ветвлений «если блокаут».
2. **Блокаут берёт общее и ничего в нём не правит.** Всё своё лежит в одной папке `Blockout/`. Нужно другое поведение — переопределение на своём экземпляре префаба в своей сцене.
3. **Изменение общего префаба — осознанное изменение обеих сцен.** Это и значит «функционал тот же».

**Проверка:** удалили папку `Blockout/` — Game компилируется и играет как раньше.

## 1. Диагноз

### 1.1. Из чего состоит Game

| Группа | Что это | Объекты |
| --- | --- | --- |
| Функционал | без этого ран не играется | `GameLifetimeScope`, `GameSession`, камеры (Main Camera, VCam, пауза, цель RTS), `BuildPlacement`, `RadialGridGuide`, `AgentSpawner`, `Headquarters` (логика и клик), `WorldAudio`, HUD |
| Декорации | мир вокруг, к логике отношения не имеет | `@Environment`, Directional Light, Global Volume, смена дня (`TimeLightController`) |
| Облик сущностей | как выглядят вещи, которые порождает ран | модели зданий, модели людей, модель пирамиды |

Вес `Game.unity` — 17 МБ: 86 систем частиц и 80 источников света, почти всё в `@Environment`.

Мусор: объект `Simulation` с `SubScene` (сцена не назначена, объект выключен).

### 1.2. Как облик сейчас связан с функционалом

- **Здание.** Префаб из `DefaultBuildingCatalog` — это одновременно данные (`BuildingStamp`: размер, стоимость, рабочие места, рецепт), функционал (`BuildingView`, звук, виджет над домом) и модель (дочерний `Body`). Из него же берётся призрак установки (весь префаб целиком, виджет прячется).
- **Люди.** Массив `characterPrefabs` прямо на `AgentViewBoard`.
- **Пирамида.** Модель лежит внутри `Headquarters` рядом с `PyramidView` и кликабельным коллайдером. Поле `PyramidView.visualRenderer` ссылается на модель, но нигде не читается.

### 1.3. Что уже хорошо

- Сетка — математика в ECS. Установка, дороги и выбор ловят курсор на математической плоскости, а не на коллайдере земли. Декорации на функционал не влияют.
- Все перекрёстные ссылки в сцене идут внутри будущего ядра или внутри декораций. Границу «функционал / декорации» не пересекает ни одна.

### 1.4. Почему не тумблер

Unity грузит всё, на что ссылается загруженная сцена, включая выключенные объекты. Переключатель «упрощённая графика» в одной сцене не экономит ни памяти, ни времени загрузки. Экономит только **отсутствие ссылки**.

## 2. Целевая форма

### 2.1. Сцена

Префиксы — палитра `M Studio / Colourful Hierarchy` (`Color Palette.asset`). Они красят строку в Hierarchy, в игре ничего не стоят. Модель пирамиды — декорация сцены, а не часть набора облика: она одна, стоит неподвижно в центре и логике не нужна.

| Префикс | Значение |
| --- | --- |
| `#` | функционал |
| `@` | декорации |
| `$` | инструменты разработчика |

```text
#GameRun                  ← префаб Prefabs/Game/GameRun.prefab, общий для обеих сцен
   #Scope                 GameLifetimeScope, GameSession
   #Cameras               Main Camera, VCam_Gameplay, PauseCamera, RTSCameraTarget
   #City                  RadialGridGuide, BuildPlacement, Headquarters (PyramidView, ClickProxy, PlazaRing, CenterTarget)
   #Agents                AgentSpawner, Humans
   #WorldAudio            AudioZoneManager, ZoneAmbienceSfxScheduler, WindAmbience
   #Hud                   GameHudCanvas
@Dressing                 SceneDressing → набор облика этой сцены
   @Lighting              Directional Light, Global Volume, DayCycle
   @Environment           своё в каждой сцене
   @Pyramid               модель пирамиды
$Dev                      только в GameBlockout
   ScenarioEditor
```

Контейнеры стоят в нуле, без поворота и масштаба.

### 2.2. Набор облика (`VisualSet`)

ScriptableObject в Content: что показать для каждого типа здания и какие модели у людей.

```csharp
public sealed class VisualSet : ScriptableObject
{
    [Serializable] public struct BuildingLook { public GameObject Building; public GameObject Body; }

    [SerializeField] BuildingLook[] buildings;   // префаб из каталога → его модель
    [SerializeField] GameObject[] workers;

    public GameObject FindBody(string typeId);
    public IReadOnlyList<GameObject> Workers;
}
```

- **Префаб здания из каталога остаётся функциональной оболочкой:** `BuildingStamp`, `BuildingView`, звук, виджет. Модели в нём больше нет.
- **Модель (`Body`) — отдельный префаб** в наборе облика. `BuildingViewBoard` ставит оболочку и вкладывает в неё модель. Призрак установки строится только из модели.
- Баланс живёт в одном месте, как и раньше. Полный разрез «данные / вид» из [[05 Content Pipeline & CMS|05]] (`BuildingDefinition`) с этой формой совместим: набор облика переедет со ссылки на префаб на ссылку на определение.

### 2.3. Кто сообщает сцене её облик

`SceneDressing` — компонент на `@Dressing` с полем `VisualSet`. `GameLifetimeScope` регистрирует его из иерархии и раздаёт `VisualSet` видам: `BuildingViewBoard`, `BuildPlacementController`, `AgentViewBoard`.

Ядро (`#GameRun`) не держит ни одной ссылки на арт. Облик приносят декорации.

### 2.4. Запуск блокаута

Только в редакторе: открыть `GameBlockout.unity` → Play. В сборку сцена не входит.

`ShellService.RestartRun` перезапускает **текущую** сцену рана, а не всегда `Game`. В редакторе `TransitionService` грузит сцену, которой нет в списке сборки, по пути (`EditorSceneManager.LoadSceneAsyncInPlayMode`). Для Game поведение не меняется.

`$Dev` / `ScenarioEditor` живёт только в блокауте: это мастерская стартового сценария (`DefaultScenario` и т.п.). `Game` в сборке редактор домов не тащит. Ран по-прежнему читает `ScenarioDefinition` с `GameSession`, не из сцены.

## 3. Фазы

| Фаза | Что | Проверка |
| --- | --- | --- |
| **Ф1** | Код: `VisualSet`, `SceneDressing`, виды берут облик из набора; призрак из модели; перезапуск текущей сцены. Модели зданий вынесены из оболочек в `Content/Visuals/Bodies`, `FullVisuals.asset` | компиляция без предупреждений |
| **Ф2** | Уборка `Game.unity` по §2.1, удаление `Simulation`/SubScene, модель пирамиды в `@Pyramid`. Сохранение `#GameRun` префабом | Play: установка, люди, пирамида, пауза, рестарт как раньше |
| **Ф3** | `Blockout/`: сцена из `#GameRun` + своих декораций, кубики зданий, капсулы людей, ступенчатая пирамида, палитра материалов | Play на `GameBlockout.unity`: тот же функционал, рестарт остаётся в блокауте |
| **Ф4** | Замер загрузки и памяти обеих сцен; проверка «удалили `Blockout/` — Game живёт»; синхронизация вики и правил | цифры в §5 |

## 4. Не делаем сейчас

- Отдельный рендерер URP без пост-эффектов для блокаута (`HeatHazeRenderFeature` и прочее). Добавляется вторым рендерером в URP-ассете и переопределением индекса на камере блокаута, Game это не трогает.
- Выбор блокаута из меню игроком («низкая графика»).
- Addressables и подгрузка декораций поверх сцены. Понадобятся, когда карт станет несколько.

### Проверено в Play

- Game, Normal: 16 жителей, предупреждения только известные (шина `bus:/Ambience`, кухня сценария на клетке c=100 r=7).
- Game, Debug-рестарт: 4 дома с моделями и коллайдерами выбора; призрак лесопилки из модели с призрачным материалом.
- Блокаут, Normal: жители — капсулы, HUD, лента, вера работают.
- Блокаут, Debug-рестарт: остался в блокауте; дома и призрак — кубы.

### Не сделано / дальше

- Время загрузки в рантайме не мерили — только граф зависимостей.
- Пост-эффекты URP (`HeatHazeRenderFeature`) в блокауте работают: рендерер общий (§4).
- Новое здание требует модели в **обоих** наборах. Нет модели — дом без вида и предупреждение в консоли.
