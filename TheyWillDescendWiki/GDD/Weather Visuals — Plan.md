# Погода — план отображения

Дата обсуждения: 2026-11-02. **План отложен, система погоды пока не реализована.** Имена классов ниже — предложенные, не существующие компоненты проекта.

Сначала доделываем варианты травы, затем камни. К контроллеру погоды возвращаемся позже. Сейчас пользователь отвечает за отображение; архитектура должна предусматривать будущий источник состояния в ECS.

## Договорённость

Один `WeatherPresenter` координирует отображение активной погоды и плавный переход между визуальными пресетами. Отдельные компоненты применяют настройки ветра, осадков, молний, атмосферы, поверхностей и звука. Не складывать всю работу с шейдерами, VFX и FMOD в один большой менеджер.

```text
Ручной выбор погоды — позже чтение состояния из ECS
                         ↓
                  WeatherPresenter
                         ↑
               WeatherVisualPreset (SO)
                         ↓
       Ветер / Осадки / Молнии / Атмосфера / Поверхности / Звук
```

Начать с одного SO на тип погоды с вложенными группами настроек. Примеры типов: обычная погода, сильный ветер, дождь, кровавый дождь, засуха, шторм с молниями. Отдельный SO для каждого небольшого эффекта или случайной вариации не требуется.

| Группа в визуальном пресете | Что хранить |
|---|---|
| Ветер | Сила, скорость, основное направление, размах и скорость общего покачивания, порывы, движение отдельных листьев |
| Осадки | Вид/ассет эффекта, интенсивность, цвет, направление |
| Молнии | Включение эффекта, диапазон интервалов, параметры вспышек |
| Атмосфера | Освещение, облачность, туман, цветовые настройки |
| Поверхности | Целевая влажность, скорости намокания и высыхания |
| Звук | Параметры ветра, осадков и грома через существующую аудиосистему |

SO содержит авторские настройки и допустимые диапазоны. Текущее изменяемое состояние хранится во время игры отдельно: активный/целевой пресет, прогресс перехода, текущие порывы, накопленная влажность. Земля после дождя должна иметь возможность высыхать постепенно.

## Три уровня разнообразия

1. **Смена типа погоды.** По явному выбору/состоянию игры переключаемся, например, на шторм. Ветер, осадки и атмосфера переходят к целевому виду плавно. Это не означает самопроизвольное превращение обычного ветра в шторм внутри визуального компонента.
2. **Вариации внутри выбранной погоды.** Шторм остаётся штормом, но меняются сила порывов, небольшие отклонения направления и интервалы эффектов. Использовать диапазоны и плавные изменения целей. Не генерировать новые случайные значения каждый кадр. Примерные числа из обсуждения — только иллюстрация: сила 1.6–2.5, интервал порывов 2–5 секунд.
3. **Различия между растениями.** Общий ветер согласован на площадке, но отдельные кусты и листья имеют небольшие различия фаз и реакции. Это задача шейдера, без собственного SO или ECS-сущности на каждую травинку. В текущем шейдере такая вариативность уже есть.

## Будущая граница ECS

- ECS определяет игровое состояние погоды, её длительность и последствия для симуляции.
- Presentation читает состояние и сопоставляет его с визуальным SO. ECS не обращается к Material, VFX, Light или FMOD и не хранит ссылки на эти объекты.
- Пока источник выбора ручной, для настройки внешнего вида. Позже его заменит чтение состояния ECS; визуальные исполнители сохранятся.
- Предусмотреть входные данные: тип погоды, интенсивность и длительность перехода. При проектировании сохранений/воспроизводимости отдельно согласовать seed и время начала.
- Если молнии впоследствии причиняют игровой ущерб, решение об ударе и его последствия принадлежит симуляции; чисто декоративные вспышки могут оставаться визуальной вариацией.

Канон связи: [[../Architecture/14 Sim Presentation Bridge|Sim ↔ Presentation Bridge]]. Способ паузы/ускорения визуальной погоды и точный формат ECS-состояния ещё не согласованы.

## Подготовка перед контроллером

В `NaturalGrassWind.hlsl` сейчас время вычисляется как `TimeSeconds * WindSpeed`, а время общего покачивания дополнительно умножается на `TuftSwaySpeed`. Изменение этих скоростей при большом накопленном времени может скачком менять фазу. Для плавных переходов погоды нужны непрерывно накапливаемые фазы общего и индивидуального движения; при смене пресета их не сбрасывать. Направление интерполировать по короткой дуге.

Материалы `M_DryGrass_01_Breeze` и `M_DryGrass_01_Storm` — образцы настроек ветра. В целевой системе пресеты меняют параметры общего материала, а не требуют нового материала на каждую вариацию погоды. Настройки других растений позже адаптируются к тому же общему ветру.
